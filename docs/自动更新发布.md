# 自动更新与 GitHub 发布

应用使用 Sparkle 2.10.0，从下列固定地址读取最新版更新信息：

`https://github.com/xiao7477/corner-folder/releases/latest/download/appcast.xml`

用户可以从菜单栏图标的右键菜单或设置窗口点击“检查更新”。应用默认每天在后台检查，发现新版后由用户确认下载和安装，安装完成后重新打开应用。

## 首次升级

GitHub 上原有 1.0.0 没有更新组件，无法自行增加更新功能。已安装 1.0.0 的用户必须手动下载安装包含此功能的 1.0.1，并把 App 拖入“应用程序”。之后才能通过应用内更新升级。

不要直接从 DMG 的只读窗口运行 App，否则更新组件无法替换应用。

## 发布新版

1. 同时增加 `app/FolderQuick/ReleaseMetadata.xcconfig` 和 `app/FolderQuick/release_metadata.sh` 的版本号与 build 号。每次正式发布，build 号必须比上一版大，Sparkle 用它判断是否有更新。
2. 写好 `releases/版本号.md`，作为 GitHub 和应用内更新的说明。
3. 在项目目录执行：

   ```bash
   app/FolderQuick/package_update.sh
   ```

   脚本会编译 Intel 和 Apple Silicon 通用版、生成 DMG 和 ZIP、签名更新包、生成并签名 `appcast.xml`。
4. 新建对应版本的 GitHub Release，例如 `v1.0.1`，上传以下文件：

   - `dist/BianbianFolder-1.0.1-universal.dmg`：首次安装使用。
   - `dist/updates/1.0.1/BianbianFolder-1.0.1-universal.zip`：应用内自动更新使用。
   - `dist/updates/1.0.1/appcast.xml`：更新信息。

5. 确认附件全部上传后，正式发布并设为 Latest。预发布和草稿不会成为这个更新入口的最新版。

本机已登录 GitHub CLI，且当前源码提交已推送到 GitHub 时，也可以运行 `app/FolderQuick/publish_release.sh` 一次性建立带三个附件的发布草稿，然后在 GitHub 确认发布。脚本默认不会直接正式发布，不会改动已有 Release。

如果缺少 `appcast.xml`，应用会报告检查更新失败；仅上传 DMG 不足以提供应用内自动更新。GitHub 源码提交也不会直接成为用户可安装的更新。

## 签名密钥

更新包和更新信息都使用 Ed25519 签名。公钥保存在应用的 `AppInfo.plist`，私钥仅保存在本机项目下的 `.update-signing/sparkle-private-key`，该目录已被 Git 忽略，不会打包进应用。

**务必将这份私钥另外做安全备份。** 后续每个版本都需要同一份私钥。不要上传到公开仓库、放入安装包、输出到日志或重新生成覆盖它。丢失私钥后，当前已发行的应用无法验证用新密钥签名的更新，用户可能需要再次手动安装。

换电脑时恢复私钥到同一路径，或通过 `SPARKLE_KEY_FILE` 指定备份路径：

```bash
SPARKLE_KEY_FILE=/安全目录/sparkle-private-key app/FolderQuick/package_update.sh
```

脚本会检查应用中的公钥与私钥是否匹配，并在不匹配时停止打包。

## 构建与验证

`build_xcode.sh`、`build_app.sh` 和 `package_dmg.sh` 都会按固定版本准备 Sparkle，并校验官方下载文件的 SHA-256。直接用 Xcode 打开工程前，先运行一次 `prepare_sparkle.sh`。

Swift Package 的依赖也固定到同一版本，并使用官方 ZIP 的校验值。

正式发行仍沿用项目现有的本地代码签名，没有新增 Apple Developer ID 和公证。更新专用签名会验证下载内容的来源与完整性；首次安装仍可能出现 macOS 的开发者验证提示。
